Course Overview · 레슨 01

Claude Code란 무엇인가?

🎬 영상 + 아티클

한 줄 정의

Claude Code는 내 코드베이스를 이해하고, 파일을 편집하고, 명령을 실행하며, 기존 개발 도구와 통합되어 일을 더 빠르게 끝내주는 에이전트형(agentic) 코딩 도구입니다. 터미널·VS Code·Claude 데스크톱 앱·웹·JetBrains IDE에서 쓸 수 있습니다.

Claude(.ai)와 무엇이 다른가

핵심 차이는 Claude Code는 AI 에이전트로 작동한다는 점입니다. Claude.ai가 코드를 복붙해 주고받는 방식이라면, Claude Code는 내 파일·터미널·코드베이스에 직접 접근해 스스로 작업을 수행합니다.

AI 에이전트란? 환경과 상호작용하며 정해진 목표를 위해 행동(action)을 수행하는 소프트웨어입니다. 본질적으로 LLM이 실시간 루프를 돌며 작동하고, 도구·외부 서비스·다른 에이전트에 접근해 목표에 도달합니다.

실제로 할 수 있는 일

능력예시
코드베이스 이해기능을 설명하거나 버그를 코드 전반에서 추적
프로젝트 전반 파일 편집함수를 리팩터하고 그것을 참조하는 모든 파일을 갱신
터미널 명령 실행빌드·테스트·패키지 설치를 실행하고 그 출력으로 다음 행동을 결정
웹 검색문서·최신 API 레퍼런스가 필요하면 직접 찾아봄

효과적으로 쓰기 위한 3가지 개념

  • 컨텍스트 윈도우 — Claude의 작업 기억. 많이 담지만 전부는 아님. 그래서 전체를 올리지 않고 전략적으로 답을 찾는 '에이전트적' 방식이 중요.
  • 권한을 물어본다 — 기본값은 명령 실행·변경 전 확인. 손이 많이 가는 방식이든 아니든 항상 내가 통제.
  • 실수할 수 있다 — 의도를 오해하거나 버그를 넣거나 과설계할 수 있음. 루프 안에 계속 있어야 일찍 잡음.

Course Overview · 레슨 02

Claude Code 작동 원리

🎬 영상 + 아티클

에이전트 루프 (Agentic Loop)

Claude Code는 일반 챗 앱과 다릅니다. 아래 루프로 이해하면 훨씬 잘 쓸 수 있습니다.

  1. 프롬프트를 입력한다.
  2. Claude가 모델과 상호작용하며 필요한 컨텍스트를 수집 → 모델은 텍스트 또는 실행할 도구 호출(tool call)을 반환.
  3. 행동을 취한다 — 예: 파일 편집, 명령 실행.
  4. 결과를 검증해 프롬프트 목표를 달성했는지 판단.
  5. 됐으면 종료하고 다음 프롬프트를 기다림. 아니면 다시 루프를 돌며 완성·검증될 때까지 반복.
루프가 도는 내내 나는 컨텍스트를 추가하거나, 중단하거나, 방향을 다시 잡아 Claude를 목표로 이끌 수 있습니다.

4가지 구성 요소

요소설명
컨텍스트대화·파일 내용·명령 출력을 담는 저장·참조 공간. 한계에 이르면 자동 compaction으로 무엇을 제거·요약할지 정해 다시 사용 가능한 크기로 줄임.
도구(Tools)에이전트의 근간. 대부분 AI가 '텍스트 in → 텍스트 out'이라면, 도구는 언제 코드를 실행해 작업에 가까워질지 결정하게 함(파일 읽기·웹 검색 등). 의미 이해로 호출 시점·사용법을 판단.
권한(Permissions)여러 모드 제공(아래).

권한 모드

모드동작
기본(Default)파일 편집·쉘 명령 전 명시적 허가를 요청
Auto-accept파일 편집은 자동 승인, 명령은 여전히 확인
Plan mode읽기 전용 도구로 먼저 실행 계획을 수립
주의 · 권한 건너뛰기는 신중히. Claude Code에 명령 실행 자유를 주면 실수를 사전에 잡기 더 어렵습니다.

Claude Code 설치하기

🎬 영상 + 아티클

터미널

macOS·Linux·WSL은 curl 한 줄로 설치합니다. Homebrew(brew install)도 되지만 자동 업데이트를 지원하지 않습니다. Windows는 PowerShell의 Invoke-RestMethod, CMD의 curl, 또는 winget(역시 자동 업데이트 없음)을 씁니다.

설치 후 프로젝트 디렉터리로 이동해 실행합니다. 안 되면 터미널을 재시작하세요.

claude

처음엔 컬러 테마 선택, Claude 계정(Pro·Max·Enterprise) 로그인 또는 API 키 설정 등 초기 단계를 거칩니다. 조직이 Enterprise 계정이면 그 옵션을 고르세요. claude를 실행한 디렉터리와 그 하위 폴더 전체에 접근합니다.

IDE·데스크톱·웹

환경설치·특징
VS CodeExtensions에서 "Claude Code"(파란 인증 체크의 Anthropic 제작) 설치 → 재시작 → Cmd/Ctrl+Shift+P로 "Claude Code Open in New Tab". 터미널과 거의 동일한 경험.
JetBrainsMarketplace에서 플러그인 설치 → IDE 재시작 → Claude 로고 클릭 시 에디터 옆 터미널 창.
DesktopClaude Desktop 로그인 후 상단 "Code" 토글. 특정 폴더에서 작업·권한 변경·클라우드 환경까지 가능.
Webclaude.ai/code 또는 사이드바 "Code". 데스크톱과 유사하나 GitHub 저장소로 제한.

무엇을 쓸까?

  • 최신 기능을 먼저 쓰고 싶다면 터미널(기능이 가장 먼저 도착).
  • 에디터와 밀착된 느낌을 원하면 IDE 통합(거의 동일한 경험).
  • 백그라운드로 돌리며 다른 일을 하려면 Desktop.
  • GitHub 저장소로 원격 작업하려면 Web.

Your first prompt · 레슨 04

첫 프롬프트

🎬 영상 + 아티클

Claude Code에는 여느 AI 어시스턴트처럼 말하면 됩니다. 다만 나를 보호하고 작업을 쉽게 하는 몇 가지를 알아두면 좋습니다.

Auto-Accept vs 승인(Approval)

파일 변경을 자동 수락할지, 매번 허가를 받을지 고를 수 있습니다. Shift + Tab으로 모드를 순환합니다.

  • Approval 모드 — 파일 편집·명령마다 허가를 요청
  • Auto-accept 모드 — 파일 편집은 자동 승인, 명령은 여전히 확인

정답은 없습니다 — 내가 편한 방식이면 됩니다.

Plan Mode

Shift + Tab 메뉴 안의 Plan Mode는 프롬프트를 받아 읽기 전용 도구로 코드베이스를 분석하고 구현 방식을 조사합니다. 중간중간 명확화 질문을 하고, 실행 가능한 상세 계획을 돌려줍니다. 복잡한 변경 계획이나 안전한 코드 리뷰에 특히 좋습니다.

예시 — 다크 모드 토글 추가: 프로젝트 루트에서 claude 실행 → Shift+Tab 두어 번으로 Plan Mode → “앱 전체에 다크 모드를 구현하고, 헤더에 라이트/다크 전환 토글을 만들어줘. 기존 라이트 테마에 맞는 대비 색을 찾아줘.” → 계획 검토 후 좋으면 수락하고 단계별 승인을 받게 함. 끝나면 Claude가 무엇을 어떻게 했는지 정확히 확인.
정리 · 프롬프트는 최대한 구체적으로. 매 단계 개입하고 싶으면 그렇게 할 수 있고, 코드 실행 전 세부를 파고들게 하려면 Plan Mode를 쓰세요.

Explore → Plan → Code → Commit

⭐ 이 코스의 핵심
이 코스에서 딱 하나만 가져간다면 이 워크플로우입니다. 이게 없으면 대부분 곧바로 “코드 짜줘”로 뛰어들고, 나중에 더 많은 교정이 필요해집니다.

① Explore & Plan (탐색·계획)

이 두 단계는 Plan Mode로 가장 빠르게 처리합니다. Plan Mode에서 Claude는 파일을 편집하지 못하고 읽기만 하며 구현 방법을 조사합니다.

“이미지 업로드 파이프라인에 WebP 변환을 추가해야 해. 파이프라인 어디서 처리해야 할지, 새 의존성이 필요한지, 어떻게 접근할지 파악해줘.”

Claude가 관련 파일을 읽고 웹 검색을 돌려 실행 계획을 제시합니다. 코드가 쓰이기 전이라 교정하기 가장 좋은 지점입니다. 변경 의도 없이 코드베이스 요약만 원하면 Plan Mode 없이 explore 서브에이전트만 돌려도 됩니다.

② Code (코드)

계획이 좋아 보이면 approve → Claude가 항목들을 처리. 편집 자동 수락/매번 확인을 고를 수 있습니다.

  • 성공 기준(success criteria)을 정의 — Claude가 “무엇이 정답인지” 명확해야 결과에 확신을 가짐. 계획에 명시.
  • 도구를 추가 — 예: 웹 UI를 만든다면 Claude in Chrome 확장을 설치해 브라우저 탭을 제어·테스트하게 함.
  • 테스트 스위트를 제공 — 계속 검증할 기준. Claude가 테스트를 써줄 수도. 넘기기 전 테스트가 신뢰할 진실인지 확인해 false positive 방지.
팁 · 같은 문제에 계속 부딪히면 그 해법을 CLAUDE.md에 저장하라고 요청하세요.

③ Commit (커밋)

직접 테스트해 만족하면 푸시할 차례입니다. 커밋 전 서브에이전트 코드 리뷰어를 돌려 작업을 검토하게 하세요 — 세션의 편향이 없는 새로운 시각. 그다음 내 스타일의 커밋 메시지를 생성하게 합니다.

  • Explore — 프로젝트에 필요한 관련 컨텍스트 확보
  • Plan — 성공을 측정할 실행 계획 수립
  • Code — 최종 결과 전까지 나와 Claude의 주고받기
  • Commit — 리뷰·푸시로 다음 기능으로 이동

컨텍스트 관리

🎬 영상 + 아티클

컨텍스트는 Claude의 작업 기억입니다. 읽는 파일, 실행하는 명령, 보내는 메시지 모두 컨텍스트 윈도우 공간을 차지합니다. 유한하므로 어떻게 쓰는지 최적화가 중요합니다.

가득 차면? — Compaction

한계에 가까워지면 자동으로 compaction이 일어나 중요한 세부를 요약하고 불필요한 도구 호출 결과를 제거해 공간을 확보합니다. 세부가 유실될 수 있음에 유의하세요.

명령어

명령동작
/compact그 지점까지 전부 압축. 이전 작업 기억은 유지하며 공간 확보.
/clear이전 세션 기억 없이 완전히 새로 시작(전부 제거).
/context컨텍스트 크기·차지 비중·시각 그래프로 상태 점검.

언제 무엇을

  • /compact — 특정 기능을 작업 중 한계에 부딪혔지만 계속 이어가야 할 때(현재 기능 관련 컨텍스트 유지).
  • /clear — 새 기능을 시작할 때(이전 대화의 편향 차단). 세션 간 기억이 필요한 건 CLAUDE.md에 넣어 재발견을 없앰.

공간 절약 팁

  • 구체적으로 — 모호한 프롬프트가 작아 보여도, 결국 Claude가 코드베이스를 더 탐색·추론하게 만들어 더 많은 컨텍스트를 씀.
  • MCP 서버 관리 — MCP는 기본적으로 모든 도구를 컨텍스트에 로드. 안 쓰는 서버는 끄기. 대신 Skills(선(先) 로드 없음)를 고려.
  • 서브에이전트 사용 — 별도 컨텍스트 윈도우에서 작업하고 요약만 반환. “인증 엔드포인트 어디 있어?”처럼 답만 필요할 때 주 컨텍스트를 깨끗이 유지.

Daily workflows · 레슨 07

코드 리뷰

🎬 영상 + 아티클

Claude Code에는 git 워크플로우를 빠르게 해주는 내장 기능이 몇 가지 있습니다.

서브에이전트로 리뷰

PR 푸시 전, 서브에이전트에게 변경을 리뷰시키세요. 서브에이전트는 자체 컨텍스트 윈도우 + 새로운 시각이라, 방금 코드를 쓴 메인 에이전트의 편향을 갖지 않습니다.

중요 · code-reviewer 서브에이전트는 읽기 전용 도구로 제한하세요. 리뷰어는 문제를 지적할 뿐 파일을 편집하지 않습니다. 설정을 저장소에 체크인하면 팀 전체가 같은 리뷰어를 사용합니다.

/commit-push-pr 스킬

커밋·푸시·PR 생성을 한 단계로 처리합니다. Slack MCP 서버를 설정하고 CLAUDE.md에 채널을 적어두면 PR 링크를 팀 채널에 자동 게시합니다.

--from-pr로 세션 연결

gh pr create로 PR을 만들면 세션이 그 PR에 자동 연결됩니다. 나중에 리뷰 코멘트 대응·빌드 수정을 위해 돌아올 때:

claude --from-pr <PR_NUMBER>

중단한 지점에서 그대로 이어집니다.

작은 기능들이지만, 일상 워크플로우의 마찰을 크게 줄여줍니다.

Customizing · 레슨 08

CLAUDE.md 파일

🎬 영상 + 아티클

Claude Code에서 가장 유용한 기능 중 하나. 프로젝트에 대한 영속적 기억을 Claude Code에 부여합니다.

해결하는 문제

CLAUDE.md가 없으면 매번 처음부터 시작합니다 — 코드베이스 재탐색, 의존성 파악, 이미 구현된 기능 이해. 종종 추측을 해서 방향 잡기가 어려워집니다. CLAUDE.md는 프로젝트 루트에 두는 Markdown 파일로, 세션 시작 때마다 자동으로 읽히고 프롬프트에 덧붙습니다. 코드베이스용 온보딩 스크립트라고 생각하세요.

예시

# Project
This is a Next.js 15 app using the App Router, Tailwind, and Drizzle ORM.

# Commands
- Dev server: `pnpm dev`
- Run tests: `pnpm test`
- Lint: `pnpm lint`

# Code Style
- Use 2-space indentation
- Prefer named exports
- All API routes go in app/api/
- Use server actions instead of API routes where possible

이제 React 컴포넌트를 만들라 하면 Tailwind를 쓰고 내 코드 규칙을 따라야 함을 이미 압니다.

팀을 위한 CLAUDE.md — 계층 구조

수준위치·용도
Project-level프로젝트 루트. 팀과 공유(버전 관리에 커밋 권장).
User-level설정 폴더. 나만, 모든 프로젝트에 적용. 개인 선호를 여기에.

팁

  • 교정을 기억에 저장 — 반복해서 고쳐주는 규칙(예: “API route 대신 server action”)은 명시적으로 메모리에 저장 요청.
  • 문서 참조 — @ 기호 + 파일 경로로 프로젝트 문서를 참조: @README.md
  • 없이 시작 — 처음엔 CLAUDE.md 없이 시작해 계속 교정하게 되는 지점을 확인하면, 꼭 필요한 정보만 담은 간결한 파일이 됨. 준비되면 /init으로 생성.

서브에이전트 (Subagents)

🎬 영상 + 아티클

Claude는 작업을 서브에이전트에게 위임해 하위 작업으로 쪼개고 병렬 실행하며, 컨텍스트 관리를 개선합니다. 각 서브에이전트는 격리된 자체 컨텍스트 윈도우에서 작동합니다.

작동 방식

코드베이스 탐색·웹 검색 같은 도구 호출은 컨텍스트를 많이 소모하지만, 그 과정에서 발견한 것이 메인 기능과 항상 관련되진 않습니다. 그래서 Claude가 “이 코드베이스를 탐색해줘” 같은 작업을 서브에이전트에 맡기면, 서브에이전트가 병렬로 탐색을 끝내고 요약만 돌려줍니다. 결과: 여정의 잡동사니 없이 원하는 답만 얻어 메인 컨텍스트가 깨끗해집니다.

내 서브에이전트 만들기

서브에이전트는 YAML frontmatter가 있는 Markdown 파일로 정의합니다. 가장 쉬운 방법은 Claude에게 생성시키는 것:

/agents

“Create new agent” 선택 → 범위·목적·접근 도구·색상까지 단계별로 정합니다. Claude가 이름·설명·프롬프트를 생성하고, 어떤 프롬프트에서 이 서브에이전트를 호출할지도 정해줍니다.

추가 커스터마이징

  • 영속 메모리 — 대화 간 기억 유지. 같은 프로젝트에 꾸준히 쓸 때 유용.
  • 스킬 프리로드 — skill 키에 스킬 이름을 나열. 단, 메인 대화와 달리 스킬 전체가 컨텍스트에 로드됨.
더 깊이 배우려면 전용 코스 Introduction to subagents를 참고하세요.

Skills

🎬 영상 (개요)

이 레슨은 영상 중심으로, 별도 아티클 본문은 짧습니다. 핵심만 정리하면:

  • Skills는 이름·설명만 컨텍스트에 올려두고, 필요하다고 판단될 때만 전체 내용을 로드하는 전문성 패키지입니다. MCP 서버가 모든 도구를 선(先) 로드하는 것과 대비되어 컨텍스트에 훨씬 가볍습니다.

MCP (Model Context Protocol)

🎬 영상 + 아티클

MCP는 Claude Code를 외부 도구·데이터 소스에 연결하는 개방 표준입니다. 질문하면 Claude가 언제 그 도구를 써야 하는지 자동으로 이해합니다. 컨텍스트의 상당 부분은 코드베이스 밖(데이터베이스·생산성 앱·공개 저장소)에 있고, MCP가 그 간극을 메웁니다.

도구(tools)는 에이전트가 행동을 수행하게 해줍니다(텍스트 응답만 받는 일반 AI와 다름). 예: 팀이 Linear를 쓰면 Linear MCP로 특정 이슈를 가져오고, 최신 의존성 문서가 필요하면 Context7 같은 docs MCP를 붙입니다.

서버 추가

claude mcp add
유형설명
HTTP 서버원격 서비스용. 제공자가 호스팅, 네트워크로 연결.
Stdio 서버내 컴퓨터에서 도는 로컬 프로세스용.

세션 안에서 /mcp로 연결 상태를 보고 필요 없는 서버를 끌 수 있습니다.

스코프 (범위)

스코프범위
Local현재 프로젝트, 나만.
User내 모든 프로젝트.
Project.mcp.json을 버전 관리에 체크인 → 팀 전원이 동일 서버를 자동 획득.

컨텍스트 비용

MCP 서버는 안 쓸 때도 도구 정의를 컨텍스트에 추가합니다. 많으면 가용 공간을 잠식하니 /mcp로 확인해 안 쓰는 건 끄세요. CLI 등가물(gh·aws)이 있으면 CLI가 더 컨텍스트 효율적입니다. Skill도 대안. MCP 도구가 컨텍스트의 10%를 초과하면 Claude Code가 tool search 모드로 전환해 필요 시 도구를 탐색합니다(신뢰성은 다소 낮을 수 있음).

Hooks

🎬 영상 + 아티클

Hooks는 Claude Code 생명주기의 특정 지점에서 명령을 실행하게 합니다. 다른 모든 것과의 결정적 차이는 결정론적(deterministic) — 언제나 실행된다는 점입니다.

CLAUDE.md에 “편집 후 Prettier 실행”이라 적으면 대개는 하지만 가끔 안 합니다. Hook은 예외 없이 매번 하게 만듭니다.

대표 용도

  • 파일 편집 후 자동 포매팅
  • 컴플라이언스용 실행 명령 로깅
  • 프로덕션 파일 수정 같은 위험 작업 차단
  • 작업 완료 시 알림 전송

작동 방식 — 이벤트

settings.json에서 이벤트를 고르고, 선택적 matcher(적용 도구)와 실행 명령을 지정합니다. /hooks 명령으로도 설정합니다.

이벤트시점
PreToolUse도구 호출 전
PostToolUse도구 호출 완료 후
UserPromptSubmit프롬프트 제출 시(Claude 처리 전)
StopClaude가 응답을 끝냈을 때
NotificationClaude가 알림을 보낼 때

실전 예시 & 차단

가장 흔한 훅은 편집 후 자동 포매팅 — PostToolUse에 matcher Edit|MultiEdit|Write를 걸어 파일 수정 때마다 확장자에 맞는 포매터(Prettier·gofmt 등)를 실행합니다.

PreToolUse 훅은 실행 전 차단할 수 있습니다. 도구 이름·입력을 JSON stdin으로 받고, exit code로 동작이 결정됩니다:

Exit code동작
0정상 진행
2차단. stderr 메시지가 Claude에 피드백으로 전달돼 이유를 알고 조정.
기타비차단 오류(사용자에게 표시되나 중단 안 함).

이렇게 하드 룰을 강제합니다 — 프로덕션 설정 디렉터리 쓰기 차단, rm -rf 포함 명령 차단, main 커밋 차단 등.

팀 공유 · .claude/settings.json의 훅은 프로젝트 수준이라 저장소에 체크인하면 팀 전원이 동일 훅을 자동 획득. 명령에서 CLAUDE_PROJECT_DIR 환경변수로 프로젝트 스크립트를 참조하면 작업 디렉터리와 무관하게 동작.

매번 실패 없이 일어나야 할 일이라면, 프롬프트에 넣지 말고 훅에 넣으세요.
