코딩 어시스턴트란?

🎬 영상 + 요약

코딩 어시스턴트는 단순히 코드를 써주는 도구가 아니라, 언어 모델을 이용해 복잡한 프로그래밍 과제를 해결하는 시스템입니다. 내부 동작을 이해하면 무엇이 진짜 강력한 코딩 동반자를 만드는지 알 수 있습니다.

코딩 어시스턴트의 작동 방식

에러 메시지를 보고 버그를 고치는 것 같은 작업을 주면, 어시스턴트는 사람 개발자와 비슷한 절차를 밟습니다.

  • 컨텍스트 수집 — 에러가 무엇을 가리키는지, 코드베이스의 어느 부분이 영향을 받는지, 어떤 파일이 관련 있는지 파악
  • 계획 수립 — 코드를 바꾸고 테스트를 돌려 수정을 검증하는 등 해결 방법 결정
  • 행동 실행 — 파일을 실제로 수정하고 명령을 실행해 해결책 구현
핵심 통찰: 첫 단계와 마지막 단계는 외부 세계와 상호작용해야 합니다 — 파일 읽기, 문서 가져오기, 명령 실행, 코드 편집.

도구 사용(tool use)의 난제

언어 모델은 그 자체로는 텍스트를 입력받아 텍스트를 반환할 뿐, 파일을 읽거나 명령을 실행할 수 없습니다. 단독 언어 모델에게 파일을 읽어달라 하면 그런 능력이 없다고 답합니다. 그럼 어떻게 해결할까요? "tool use"라는 영리한 시스템을 씁니다.

도구 사용은 어떻게 동작하나

요청을 보낼 때, 어시스턴트가 메시지에 행동을 요청하는 법을 가르치는 지침을 자동으로 덧붙입니다. 예: "파일을 읽고 싶으면 'ReadFile: 파일명'으로 응답하라". 전체 흐름은 이렇습니다.

  • 사용자: "main.go 파일에 어떤 코드가 있나?"
  • 어시스턴트가 요청에 도구 지침을 추가
  • 언어 모델: "ReadFile: main.go"
  • 어시스턴트가 실제 파일을 읽어 그 내용을 모델에 다시 전달
  • 모델이 파일 내용을 근거로 최종 답변 제공

이 시스템 덕에 모델은 실제로는 형식에 맞춘 텍스트를 생성할 뿐인데도 "파일 읽기", "코드 쓰기", "명령 실행"을 사실상 해낼 수 있습니다.

왜 Claude의 도구 사용이 중요한가

모든 언어 모델이 도구를 똑같이 잘 쓰는 건 아닙니다. Claude 계열 모델은 도구가 무엇을 하는지 이해하고 효과적으로 사용하는 데 특히 강합니다.

강한 도구 사용의 이점

  • 더 어려운 과제 처리 — 여러 도구를 조합해 복잡한 일을 다루고, 처음 보는 도구도 사용
  • 확장 가능한 플랫폼 — 새 도구를 쉽게 추가하고, 워크플로우가 진화하면 Claude가 적응
  • 더 나은 보안 — 인덱싱 없이 코드베이스를 탐색 → 전체 코드베이스를 외부 서버로 보내지 않는 경우가 많음
  • 코딩 어시스턴트는 언어 모델로 다양한 작업을 수행
  • 대부분의 실전 프로그래밍 작업엔 도구가 필요
  • 모델마다 도구 사용 능력이 다름
  • Claude의 강한 도구 사용이 보안·커스터마이징·수명을 뒷받침

Claude Code 설치

🎬 영상 + 요약

Claude Code를 로컬에 설치할 차례입니다. 전체 설치 안내는 공식 quickstart 문서에서 확인할 수 있습니다.

설치

MacOS, Linux, WSL:      curl -fsSL https://claude.ai/install.sh | bash
Windows PowerShell:     irm https://claude.ai/install.ps1 | iex
Windows Command Prompt:  curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd
MacOS (Homebrew):       brew install --cask claude-code
  • 설치 후 터미널에서 claude 실행. 첫 실행 시 색상 테마 선택과 claude.ai 계정 인증 안내가 뜹니다.
문제 해결 · 설치 후 claude를 못 찾거나 네트워크·권한 에러가 나면 문서의 "Troubleshoot installation issues"를 참고하세요. Amazon Bedrock·Google Cloud Vertex AI·Microsoft Foundry로 쓴다면 서드파티 제공자 설정 안내가 별도로 있습니다.

프로젝트 세팅

🎬 영상 + 요약

실습에 쓸 작은 프로젝트가 있으면 Claude Code를 다루기가 더 흥미롭습니다. 강의에서는 이전 영상에 나온 것과 같은 UI 생성 앱을 제공합니다. (꼭 이 프로젝트를 돌릴 필요는 없고, 원하는 자신의 코드베이스로 따라가도 됩니다.)

세팅

  • 로컬에 Node JS 설치 확인
  • 강의에 첨부된 uigen.zip을 내려받아 압축 해제
  • 프로젝트 디렉터리에서 npm run setup — 의존성 설치 + 로컬 SQLite DB 구성
  • (선택) 이 앱은 Anthropic API로 UI 컴포넌트를 생성합니다. 완전히 테스트하려면 API 키가 필요합니다. 건너뛰어도 정적 가짜 코드는 생성됩니다.
    • console.anthropic.com에서 API 키 발급
    • .env 파일의 your-api-key-here 자리에 실제 키를 넣기
  • npm run dev로 프로젝트 시작

컨텍스트 추가

🎬 영상 + 요약
영상은 제거된 옛 # "메모리 모드" 단축키를 보여줍니다. 아래 텍스트대로 /memory와 CLAUDE.md 직접 편집을 사용하세요.

코딩 작업에서 컨텍스트 관리는 매우 중요합니다. 프로젝트에 수십·수백 개 파일이 있어도 Claude에는 맞는 정보만 필요합니다. 관련 없는 컨텍스트가 너무 많으면 오히려 성능이 떨어지므로, 관련 파일·문서로 안내하는 법을 익혀야 합니다.

/init 명령

새 프로젝트에서 Claude를 처음 시작할 때 /init을 실행하면, Claude가 코드베이스 전체를 분석해 다음을 파악합니다.

  • 프로젝트의 목적과 아키텍처
  • 중요한 명령과 핵심 파일
  • 코딩 패턴과 구조

분석 후 Claude는 요약을 만들어 CLAUDE.md 파일에 씁니다. 파일 생성 권한을 물을 때 Enter로 매 쓰기를 승인하거나, Shift+Tab으로 세션 내내 자유롭게 쓰도록 허용할 수 있습니다.

CLAUDE.md 파일

CLAUDE.md의 두 가지 목적:

  • 중요한 명령·아키텍처·코딩 스타일을 짚어주며 Claude를 코드베이스 안내
  • Claude에 구체적·커스텀 지시를 부여
이 파일은 모든 요청에 포함됩니다 — 프로젝트별 영속 시스템 프롬프트를 갖는 셈.

CLAUDE.md의 세 위치

파일용도
CLAUDE.md/init으로 생성, 소스 관리에 커밋, 다른 엔지니어와 공유
CLAUDE.local.md공유하지 않음 — 개인 지시·커스터마이징
~/.claude/CLAUDE.md내 머신의 모든 프로젝트에 적용되는 지시

커스텀 지시 추가

CLAUDE.md에 지시를 넣어 동작을 조정합니다. 예를 들어 주석을 너무 많이 단다면, 에디터에서 직접 편집하거나 /memory로 파일을 열어 Use comments sparingly. Only comment complex code 같은 지시를 추가합니다. Claude는 대화 시작마다 이 파일을 읽으므로 다음 메시지부터 적용됩니다.

'@'로 파일 언급

특정 파일을 보게 하려면 @ 뒤에 파일 경로를 붙입니다. 그 파일 내용이 요청에 자동 포함됩니다.

How does the auth system work? @auth

Claude가 auth 관련 파일 목록을 보여주고, 선택한 파일을 대화에 포함합니다.

CLAUDE.md 안에서 파일 참조

CLAUDE.md 안에서도 같은 @ 문법을 쓸 수 있습니다. 여러 곳에 관련되는 파일(예: DB 스키마)에 특히 유용합니다.

The database schema is defined in the @prisma/schema.prisma file. Reference it anytime you need to understand the structure of data stored in the database.

이렇게 언급하면 그 내용이 매 요청에 자동 포함돼, 매번 스키마를 찾아 읽지 않고도 데이터 구조를 바로 답할 수 있습니다.

이미 다른 도구용 AGENTS.md가 있다면 중복할 필요 없이, CLAUDE.md 첫 줄에 @AGENTS.md를 추가하면 그 내용을 먼저 로드합니다. 아래에 Claude 전용 지시를 덧붙이면 됩니다.

변경 만들기

🎬 영상 + 요약
영상은 이제 효과가 없는 옛 "think harder" 키워드를 보여줍니다. 아래 텍스트대로 /effort를 사용하세요.

기존 프로젝트에 변경을 만들 때 유용한 실전 기법 — 스크린샷을 통한 시각적 소통과 Claude의 추론 능력 활용을 다룹니다.

스크린샷으로 정확히 소통하기

인터페이스의 특정 부분을 수정할 때 스크린샷을 붙이면 Claude가 무엇을 가리키는지 정확히 이해합니다. 붙여넣기는 Ctrl+V를 씁니다(macOS에서도 Cmd+V가 아님). 이미지를 붙인 뒤 해당 영역에 대한 구체적 변경을 요청하면 됩니다.

플래닝 모드

코드베이스 전반을 폭넓게 조사해야 하는 복잡한 작업엔 플래닝 모드를 켭니다. /plan을 입력하거나 Shift+Tab을 두 번(이미 자동 수락 중이면 한 번) 눌러 활성화합니다. 이 모드에서 Claude는:

  • 프로젝트의 더 많은 파일을 읽음
  • 상세한 구현 계획을 작성
  • 무엇을 할지 정확히 보여줌
  • 승인 전까지 대기
계획을 검토할 때 Ctrl+G로 텍스트 에디터에서 열 수 있습니다. 승인 전에 정밀하게 편집하면 Claude가 최종본을 반영합니다.

Effort 레벨 — Claude가 얼마나 깊이 생각하나

기본적으로 Claude는 답하기 전에 추론합니다("still thinking" 힌트). 실제 추론 단계를 펼쳐 보려면 Ctrl+O를 누릅니다. /effort로 현재 레벨을 확인·조정하세요 — low는 빠르고 저렴, max는 어려운 문제에 가장 오래 추론합니다. 기본값은 모델·플랜에 따라 다릅니다.

단일 프롬프트에서만 더 생각하게 하려면 프롬프트에 ultrathink 키워드를 넣으세요 — 그 턴만 추론을 늘리고 세션 effort 레벨은 바꾸지 않습니다.

플래닝 vs Effort — 언제 무엇을

플래닝 모드가 좋은 경우높은 effort가 좋은 경우
코드베이스의 넓은 이해가 필요, 다단계 구현, 여러 파일·컴포넌트에 영향복잡한 로직 문제, 어려운 디버깅, 알고리즘 난제

넓이와 깊이를 모두 요하는 작업엔 둘을 조합할 수 있습니다. 다만 둘 다 추가 토큰을 소비하므로 비용을 고려하세요.

컨텍스트 흐름 제어

🎬 영상 + 요약
영상은 메모리 추가용 옛 # 단축키를 보여줍니다. 아래 텍스트대로 /memory를 사용하세요.

복잡한 작업에선 대화를 집중·생산적으로 이끌기 위해 흐름을 제어해야 합니다. 몇 가지 기법이 있습니다.

Escape로 Claude 중단

Claude가 엉뚱한 방향으로 가거나 너무 많은 일을 한꺼번에 하려 하면 Escape로 응답 중간에 멈추고 방향을 다시 잡을 수 있습니다. 예: 여러 함수의 테스트를 한꺼번에 계획하려 할 때 멈추고 한 함수씩 집중하게 합니다.

Escape + 메모리

반복 실수를 고치는 데 특히 강력합니다.

  • Escape로 현재 응답 중단
  • /memory(또는 CLAUDE.md 직접 편집)로 올바른 방식 메모 추가
  • 수정된 정보로 대화 계속

이렇게 하면 앞으로의 대화에서 같은 실수를 막습니다.

대화 되감기(rewind)

긴 대화에선 무관한 컨텍스트가 쌓입니다(예: 에러 디버깅의 왕복). Escape 두 번 또는 /rewind로 이전 지점으로 되돌아갑니다. 장점:

  • 코드베이스 이해 같은 가치 있는 컨텍스트 유지
  • 산만한 이력 제거
  • 현재 작업에 집중

컨텍스트 관리 명령

명령설명
/compact대화 이력을 요약하되 Claude가 배운 핵심 정보는 보존. 값진 지식을 쌓았고 관련 작업을 이어갈 때 이상적.

커스텀 명령 만들기

  • 프로젝트의 .claude 폴더를 찾음
  • 그 안에 commands 디렉터리 생성
  • 원하는 명령 이름의 마크다운 파일 생성(예: audit.md)

예시: audit 명령

프로젝트 의존성의 취약점을 점검하는 커스텀 명령 예시는 세 가지를 합니다.

  • npm audit으로 취약 패키지 탐색
  • npm audit fix로 업데이트 적용
  • 테스트를 돌려 업데이트가 무언가를 깨지 않았는지 검증

파일을 만들면 Claude Code가 자동으로 인식합니다 — 재시작 불필요.

인자를 받는 명령

$ARGUMENTS 플레이스홀더로 인자를 받아 훨씬 유연·재사용 가능하게 만듭니다. 예: write_tests.md

Write comprehensive tests for: $ARGUMENTS

Testing conventions:
* Use Vitest with React Testing Library
* Place test files in a __tests__ directory in the same folder as the source file
* Name test files as [filename].test.ts(x)
* Use @/ prefix for imports

Coverage:
* Test happy paths
* Test edge cases
* Test error states

파일 경로와 함께 실행:

/write_tests the use-auth.ts file in the hooks directory

인자는 파일 경로일 필요 없이 어떤 문자열이든 될 수 있어 작업에 컨텍스트·방향을 줍니다.

MCP 서버와 Claude Code

🎬 영상 + 요약

MCP(Model Context Protocol) 서버를 추가해 Claude Code를 확장할 수 있습니다. 이 서버들은 원격 또는 로컬에서 돌며, 기본으로는 없는 새 도구·능력을 제공합니다. 가장 인기 있는 것 중 하나가 Playwright — Claude에게 웹 브라우저 제어 능력을 줍니다.

Playwright MCP 서버 설치

터미널에서(Claude Code 내부가 아님) 실행:

claude mcp add playwright npx @playwright/mcp@latest

이 명령은 서버를 "playwright"로 이름 짓고, 로컬에서 서버를 시작하는 명령을 지정합니다.

권한 관리

MCP 도구를 처음 쓸 때 Claude가 매번 권한을 묻습니다. 귀찮다면 .claude/settings.local.json에서 사전 승인합니다.

{
"permissions": {
"allow": ["mcp__playwright"],
"deny": []
}
}

mcp__playwright의 이중 언더스코어에 주의하세요. 이렇게 하면 매번 묻지 않고 Playwright 도구를 씁니다.

실전 예시: 컴포넌트 생성 개선

프롬프트를 손으로 테스트·조정하는 대신 Claude에게 이렇게 시킬 수 있습니다.

  • 브라우저를 열어 앱으로 이동
  • 테스트 컴포넌트 생성
  • 시각적 스타일·코드 품질 분석
  • 관찰 결과로 생성 프롬프트 갱신
  • 개선된 프롬프트로 새 컴포넌트 재테스트

예: "localhost:3000으로 이동해 기본 컴포넌트를 생성하고, 스타일을 검토한 뒤, @src/lib/prompts/generation.tsx의 생성 프롬프트를 더 나은 컴포넌트가 나오도록 갱신하라." Claude는 브라우저 도구로 앱과 상호작용하고, 산출물을 살펴본 뒤 프롬프트 파일을 수정합니다.

결과와 이점

실제로 훨씬 나은 결과로 이어질 수 있습니다. 밋밋한 보라→파랑 그라디언트와 표준 Tailwind 패턴 대신 Claude가 이런 방향을 유도하도록 프롬프트를 갱신할 수 있습니다.

  • 따뜻한 노을 그라디언트(오렌지→핑크→퍼플)
  • 바다 깊이 테마(틸→에메랄드→시안)
  • 비대칭 디자인·겹치는 요소
  • 창의적 여백·관습을 벗어난 레이아웃
핵심 이점: Claude가 코드뿐 아니라 실제 시각 산출물을 볼 수 있어 스타일 개선을 훨씬 잘 판단합니다.

Playwright는 시작일 뿐입니다. 생태계엔 DB 상호작용, API 테스트·모니터링, 파일시스템 조작, 클라우드 연동, 개발 도구 자동화 등을 위한 서버가 있습니다.

훅(hook) 소개

🎬 영상 + 요약

훅(hook)은 Claude가 도구를 실행하기 직전·직후에 명령을 돌리게 해줍니다. 편집 후 포매터 실행, 파일 변경 시 테스트 실행, 특정 파일 접근 차단 같은 자동화에 아주 유용합니다.

훅의 작동 방식

보통의 흐름: 질의가 도구 정의와 함께 Claude 모델에 전송 → Claude가 도구 사용을 형식에 맞춰 응답 → Claude Code가 도구를 실행하고 결과 반환. 훅은 이 과정에 끼어들어 도구 실행 직전·직후에 코드를 실행합니다.

  • PreToolUse 훅 — 도구 호출 전 실행
  • PostToolUse 훅 — 도구 호출 후 실행

훅 구성

훅은 Claude 설정 파일에 정의합니다.

  • Global — ~/.claude/settings.json(모든 프로젝트)
  • Project — .claude/settings.json(팀 공유)
  • Project(비커밋) — .claude/settings.local.json(개인)

파일에 손으로 쓰거나 Claude Code 내부에서 /hooks 명령을 씁니다. 구성 구조는 두 개의 주요 섹션을 포함합니다.

PreToolUse 훅

도구 실행 전에 돌며, 대상 도구를 지정하는 matcher를 포함합니다.

"PreToolUse": [
{
"matcher": "Read",
"hooks": [
{
"type": "command",
"command": "node /home/hooks/read_hook.js"
}
]
}
]

명령은 Claude가 하려는 도구 호출 정보를 받고, 정상 진행을 허용하거나 차단 + 에러 메시지 반환을 할 수 있습니다.

PostToolUse 훅

도구 실행 후에 돕니다. write/edit/multi-edit 뒤 트리거 예시:

"PostToolUse": [
{
"matcher": "Write|Edit",
"hooks": [
{
"type": "command",
"command": "node /home/hooks/edit_hook.js"
}
]
}
]

이미 실행됐으므로 차단은 못 하지만, 후속 작업 실행(방금 편집한 파일 포매팅 등)이나 추가 피드백 제공이 가능합니다.

실전 활용

  • 코드 포매팅 — 편집 후 자동 포맷
  • 테스트 — 파일 변경 시 자동 실행
  • 접근 제어 — 특정 파일 읽기·편집 차단
  • 코드 품질 — 린터·타입 체커 실행 후 피드백
  • 로깅 — 접근·수정 파일 추적
  • 검증 — 명명 규칙·코딩 표준 확인
PreToolUse 훅은 Claude가 할 수 있는 것을 제어하고, PostToolUse 훅은 Claude가 한 것을 강화합니다.

훅 정의하기

🎬 영상 + 요약

훅은 도구 호출을 실행 전후로 가로채고 제어하게 해줍니다. 개발 환경에서 Claude가 무엇을 할 수 있고 없는지 세밀하게 통제할 수 있습니다.

훅 만들기 — 4단계

  • Pre 또는 Post 결정 — PreToolUse는 실행을 막을 수 있고, PostToolUse는 실행 후 동작
  • 감시할 도구 종류 결정 — 어떤 도구가 훅을 트리거할지 정확히 지정
  • 도구 호출을 받을 명령 작성 — 표준 입력(stdin)으로 도구 호출 JSON을 받음
  • 필요 시 Claude에 피드백 — 명령의 exit code가 허용·차단을 결정

사용 가능한 도구

현재 셋업에서 어떤 도구가 있는지는 Claude에게 직접 목록을 물으면 됩니다. 커스텀 MCP 서버를 추가하면 도구가 바뀌므로 특히 유용합니다.

도구 호출 데이터 구조

{
"session_id": "2d6a1e4d-6...",
"transcript_path": "/Users/sg/...",
"hook_event_name": "PreToolUse",
"tool_name": "Read",
"tool_input": {
"file_path": "/code/queries/.env"
}
}

명령은 이 JSON을 stdin에서 읽어 파싱한 뒤, tool name과 input을 근거로 허용·차단을 결정합니다.

Exit code와 제어 흐름

Exit code의미
0이상 없음 — 도구 호출 진행 허용
2도구 호출 차단(PreToolUse 전용)
PreToolUse에서 code 2로 종료하면, stderr에 쓴 에러 메시지가 Claude에 피드백으로 전달돼 왜 막혔는지 설명합니다.

대표 사례: .env 같은 민감 파일 읽기 방지. Read와 Grep 둘 다 파일 내용에 접근하므로 두 도구를 감시하고 제한 경로 접근인지 확인합니다.

훅 구현하기

🎬 영상 + 요약
영상은 Grep을 포함한 이전 버전 연습을 보여줍니다. 아래 텍스트가 현재 버전입니다.

Claude가 민감 파일을 읽지 못하게 막는 훅을 만들어봅니다. PreToolUse 훅이 실행 전에 도구 호출을 가로채는 실전 예시입니다. 이 연습에선 Read 도구가 .env를 여는 것을 차단해 세션 중 환경 변수를 보호합니다.

이 훅은 Read만 다룹니다. Grep·Bash가 같은 파일에 닿는 것까지 막으려면 도구별 입력 형태를 따로 검사해야 합니다. 포괄적 보호에는 훅과 permissions.deny 규칙(예: "Read(**/.env)")을 병행하세요.

훅 구성

.claude/settings.local.json을 열어 Read를 매칭하는 PreToolUse 훅을 추가합니다.

{
"hooks": {
"PreToolUse": [
{
"matcher": "Read",
"hooks": [
{ "type": "command", "command": "node $PWD/hooks/read_hook.js" }
]
}
]
}
}

훅 스크립트 작성

hooks/read_hook.js 생성:

process.stdin.setEncoding("utf8");
let input = "";
process.stdin.on("data", (d) => (input += d));
process.stdin.on("end", () => {
const toolArgs = JSON.parse(input);
const readPath = toolArgs.tool_input?.file_path || "";
if (readPath.includes(".env")) {
console.error("You cannot read the .env file");
process.exit(2);
}
process.exit(0);
});

훅은 stdin에서 도구 호출 JSON을 읽어 tool_input.file_path를 확인하고, code 2로 종료해 차단합니다(stderr에 쓴 내용이 Claude가 보는 메시지).

테스트

세션에서 Claude에게 .env를 읽어달라 하면 다음이 보입니다.

You cannot read the .env file

훅이 Read 호출을 막은 것입니다. 다른 파일을 읽어달라 하면 정상 동작합니다.

왜 Read만?

도구마다 입력 형태가 다릅니다. Read는 {"file_path": "..."}, Grep은 {"pattern": "...", "path": "..."}(여기서 path는 파일이 아닌 검색 디렉터리), Bash는 {"command": "..."}. file_path 검사는 Read는 잡지만 API_KEY 전역 grep이나 cat .env는 못 잡습니다. 이를 커버하려면 도구별 matcher를 따로 쓰거나, 도구 전반에 균일하게 적용되는 permissions.deny 규칙을 쓰세요.

훅의 함정(gotchas)

🎬 영상 + 요약

npm run setup 후 .claude 디렉터리에 settings.json 파일이 두 개 생기는 이유를 설명합니다.

Claude Code 문서는 훅 보안 권장 사항을 안내합니다.

그중 하나가 스크립트에 상대 경로가 아닌 절대 경로를 쓰라는 것입니다 — 경로 가로채기·바이너리 심기 공격을 완화합니다.

하지만 절대 경로는 settings.json 공유를 어렵게 합니다 — 프로젝트 위치가 사람마다 달라 절대 경로가 다르기 때문입니다.

이를 해결하려고 프로젝트엔 settings.example.json이 있고, 스크립트 참조에 $PWD 플레이스홀더를 씁니다. npm run setup이 실행하는 init-claude.js 스크립트가 $PWD를 내 머신의 절대 경로로 치환하고, 파일을 복사해 settings.local.json으로 이름을 바꿉니다. 덕분에 권장 절대 경로를 쓰면서도 설정 파일을 공유할 수 있습니다.

유용한 훅들!

🎬 영상 + 요약

훅은 특히 큰 프로젝트에서 AI 보조 개발의 흔한 약점을 보완합니다. Claude가 코드를 바꿀 때 자동으로 돌아 즉각 피드백을 주고 문제를 예방합니다.

TypeScript 타입 체크 훅

근본 문제 하나: Claude가 함수 시그니처를 바꾸면, 프로젝트 곳곳의 호출부를 다 갱신하지 못하는 경우가 많습니다. 예를 들어 schema.ts 함수에 verbose 파라미터를 추가하라 하면 정의는 바꾸지만 main.ts의 호출부는 놓칩니다. 해법은 편집 후 TypeScript 컴파일러를 돌리는 post-tool-use 훅입니다.

  • tsc --noEmit으로 타입 에러 검사
  • 발견된 에러 캡처
  • Claude에 즉시 피드백
  • 다른 파일의 문제를 고치도록 유도

타입 체커를 돌릴 수 있는 언어면 무엇이든 동작합니다. 무타입 언어라면 자동화 테스트로 비슷하게 구현할 수 있습니다.

쿼리 중복 방지 훅

DB 쿼리가 많은 큰 프로젝트에선 Claude가 기존 코드를 재사용하지 않고 중복 기능을 만들 때가 있습니다. "3일 넘게 대기 중인 주문을 알리는 Slack 통합을 만들라" 같은 복합 작업에서 기존 getPendingOrders() 대신 새 쿼리를 쓰는 식입니다.

쿼리 중복 방지 훅은 리뷰 프로세스를 구현합니다.

  • ./queries 디렉터리 수정 시 트리거
  • 별도의 Claude Code 인스턴스를 프로그래밍적으로 실행
  • 두 번째 인스턴스에 변경 검토·유사 기존 쿼리 확인 요청
  • 중복 발견 시 원래 인스턴스에 피드백
  • 중복 제거·기존 기능 사용을 유도

구현 고려사항

TypeScript 훅은 가볍고 빠르지만, 쿼리 중복 훅은 리뷰마다 별도 Claude 인스턴스를 띄워 자원을 더 씁니다.

  • 이점 — 중복 없는 깔끔한 코드베이스
  • 비용 — 쿼리 디렉터리 편집마다 추가 시간·API 사용
  • 권장 — 핵심 디렉터리만 감시해 오버헤드 최소화

이 훅들은 Claude의 Agent SDK로 AI와 프로그래밍적으로 상호작용해, 한 인스턴스가 다른 인스턴스의 작업을 리뷰·피드백하는 정교한 워크플로우를 만듭니다.

  • 컴파일러·린터 출력으로 즉각 피드백
  • 별도 AI 인스턴스로 코드 리뷰 프로세스 구현
  • 일관성이 중요한 고가치 디렉터리에 감시 집중
  • 자동화 이점과 성능 비용의 균형

또 다른 유용한 훅

🎬 영상 + 요약

PreToolUse·PostToolUse 외에도 여러 훅이 있습니다.

훅시점
Notification알림 발생 시(도구 권한 필요, 또는 60초 유휴 후)
StopClaude Code가 응답을 마쳤을 때
SubagentStop서브에이전트("Task"로 표시)가 끝났을 때
PreCompactcompact(수동·자동) 직전
UserPromptSubmit사용자가 프롬프트를 제출할 때(Claude 처리 전)
SessionStart세션 시작·재개 시
SessionEnd세션 종료 시
헷갈리는 점: stdin 입력 형태가 훅 타입에 따라(Pre/Post/Notification…) 달라지고, PreToolUse·PostToolUse의 tool_input은 호출된 도구에 따라 또 달라집니다.

TodoWrite를 감시하는 PostToolUse 훅의 stdin 예시:

{
"session_id": "9ecf22fa-edf8-4332-ae85-b6d5456eda64",
"transcript_path": "",
"hook_event_name": "PostToolUse",
"tool_name": "TodoWrite",
"tool_input": {
"todos": [{ "content": "write a readme", "status": "pending", "id": "1" }]
},
"tool_response": {
"oldTodos": [],
"newTodos": [{ "content": "write a readme", "status": "pending", "id": "1" }]
}
}

비교용 Stop 훅 입력:

{
"session_id": "af9f50b6-f042-4773-b3e2-c3a4814765ce",
"transcript_path": "",
"hook_event_name": "Stop",
"stop_hook_active": false
}

이처럼 stdin 입력이 훅과 matcher에 따라 크게 달라져 훅 작성이 까다롭습니다 — 입력 구조를 미리 모를 수 있습니다.

디버깅 팁 · 입력을 파일에 기록하는 헬퍼 훅을 만들어 실제로 어떤 데이터가 들어오는지 들여다보세요.
"PostToolUse": [ // Or "PreToolUse" or "Stop", etc
{
"matcher": "*",
"hooks": [
{
"type": "command",
"command": "jq . > post-log.json"
}
]
},
]

이 명령은 훅 입력을 post-log.json에 써서, 내 명령이 무엇을 검사해야 하는지 정확히 파악하게 해줍니다.

Programmatic use · 레슨 18

Claude Code SDK

🎬 영상 + 요약
영상은 더 이상 동작하지 않는 옛 패키지명을 씁니다. 아래 텍스트가 현재 버전입니다.

Agent SDK는 Claude Code를 내 애플리케이션·스크립트에서 프로그래밍적으로 돌리게 해줍니다. TypeScript·Python용이 있으며, CLI가 쓰는 것과 같은 에이전트 루프(파일 읽기·편집·도구 사용)를 내 통제 아래 제공합니다.

설치

mkdir sdk-demo
cd sdk-demo
npm init -y
npm install @anthropic-ai/claude-agent-sdk

패키지는 @anthropic-ai/claude-agent-sdk입니다. (비슷한 이름의 @anthropic-ai/claude-code는 CLI 자체라 import할 수 없습니다.)

최소 예시

index.mjs를 만들어 붙여넣습니다.

import { query } from "@anthropic-ai/claude-agent-sdk";

const prompt = "List the files in the current directory";

for await (const message of query({ prompt })) {
console.log(JSON.stringify(message, null, 2));
}

실행:

node index.mjs

CLI에서 보던 것과 같은 대화 이벤트 — 도구 호출, 도구 결과, Claude의 텍스트 — 가 JSON 스트림으로 나옵니다.

도구 제한

기본적으로 SDK는 전체 도구 세트에 접근합니다. 좁히려면 allowedTools를 넘깁니다(CLI의 --allowedTools와 동등).

for await (const message of query({
prompt,
options: { allowedTools: ["Read", "Glob"] },
})) {
// ...
}
SDK는 CLI가 하는 모든 것 — 커스텀 시스템 프롬프트, MCP 서버, 훅, 서브에이전트, 세션 재개 — 을 지원합니다. 전체 레퍼런스는 Agent SDK 문서를 참고하세요.
