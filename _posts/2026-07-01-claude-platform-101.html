Claude Developer Platform이란?

🎬 영상

Claude Developer Platform은 Claude를 프로그래밍으로(programmatically) 활용하기 위한 Anthropic의 인프라입니다. 브라우저에서 대화하는 대신, 코드에서 구조화된 요청을 보내고 구조화된 응답을 받으며 — 모델·토큰·도구·시스템 지침까지 모든 세부를 제어합니다.

  • 어떤 언어에서든 호출하는 REST API
  • 언어별 SDK와 CLI
  • API 키·사용량·매니지드 에이전트·프롬프트 테스트를 관리하는 Console

플랫폼의 3계층

계층내용
Primitives (빌드)Messages API, 도구 사용, files, 웹 검색, 코드 실행, MCP 서버, Skills — 코드에서 직접 호출하는 조각들.
Infrastructure (확장)매니지드 에이전트, 재시도, 큐, 관측성 — 한 번의 호출이 천 번이 돼도 굴러가게 하는 배관.
Controls (운영)대시보드, evals 등 프로덕션에서 돌리는 다이얼.
한 줄 요약: Primitives로 만들고, Infrastructure로 확장하고, Controls로 운영한다.

예시 — 헬프데스크 답변 초안

티켓 내용을 기반으로 팀의 톤·가이드라인에 맞춰 답변 초안을 만드는 기능은 Messages API의 전형적 사례입니다.

response = client.messages.create(
    model="claude-haiku-4-5",   # 단순 초안엔 Haiku가 적합
    max_tokens=1024,
    system=TONE_AND_GUIDELINES, # 시스템 프롬프트 = Claude의 역할
    messages=[{"role": "user", "content": ticket_content}],
)
draft = response.content

핵심은 챗봇을 새로 만드는 게 아니라, 이미 존재하는 제품에 Claude를 끼워 넣는 것입니다. “Claude에게 질문하기”에서 “Claude가 내 제품의 일부가 되기”로.

첫 API 호출

🎬 영상

준비

  • platform.claude.com에서 API 키 발급(크레딧 구매 필요).
  • 키는 .env.local에 저장 — 소스에 하드코딩하면 GitHub에 유출됩니다.
  • SDK 설치: npm install @anthropic-ai/sdk

요청의 해부 — messages.create

모든 호출은 messages.create를 거치며 model · max_tokens · messages 세 가지를 지정합니다.

const response = await client.messages.create({
  model: "claude-opus-4-8",
  max_tokens: 1024,
  system: "You are a terse senior code reviewer. Give feedback in one paragraph.",
  messages: [{ role: "user", content: `Review this code:\n${buggyCode}` }],
});

for (const block of response.content) {
  if (block.type === "text") console.log(block.text);
}
  • system 프롬프트에서 페르소나를 빚습니다(“간결한 시니어 리뷰어”).
  • 응답 content는 문자열이 아니라 블록 배열 — text·tool call·thinking이 섞일 수 있어 항상 루프를 돌며 type을 확인합니다.
실제 제품에선 이 동일한 messages.create가 “요약 엔드포인트”의 엔진이 됩니다 — DB에서 회의록을 꺼내 시스템 프롬프트와 함께 넘기고, 결과를 저장·반환. 같은 호출을 라우트 핸들러로 감쌌을 뿐.

알맞은 모델 고르기

🎬 영상

제일 똑똑한 모델을 기본값으로 쓰면 청구서가 놀라게 하고, 제일 싼 걸 쓰면 출력이 못 버팁니다. 각 모델은 트레이드오프가 다릅니다.

티어용도
FableOpus 위의 최상위 티어(가장 강력·고비용). 가장 어려운 과제에만. (강의 촬영 시점엔 미출시)
Opus핵심 3종 중 가장 유능하나 가장 느리고 비쌈. 깊은 추론·복잡 분석·다단계 코딩·미묘한 글쓰기.
Sonnet지능·속도·비용의 스위트 스팟 — 대부분의 프로덕션 작업.
Haiku가장 빠르고 저렴. 분류·추출·라우팅 등 대량·저복잡 작업.

간단한 eval부터

프로덕션 코드를 짜기 전, 실제 워크로드에서 대표 예시 20~30개를 각 모델에 돌려 “좋은 출력” 기준으로 채점하세요. 그리고 티어를 올려가며:

  1. 먼저 Haiku로 — 품질이 버티면 끝(비용 대폭 절약).
  2. 아니면 Sonnet으로.
  3. 정말 필요할 때만 Opus.
핵심: “실제로 출시할 만한 출력 중 가장 싼 모델”이 정답. response.usage가 입력·출력 토큰(=청구 근거)을 돌려줍니다.

실제 앱에선 한 엔드포인트 안에서 작업별로 라우팅합니다 — 파일 분류는 Haiku, 고객 업데이트 초안은 Sonnet, RFP 응답만 Opus.

에이전트 루프

🎬 영상

단일 호출은 한 번의 응답만 줍니다. 워크플로우를 자동화하려면 Claude가 행동 → 결과 확인 → 다음 결정을 반복해야 합니다. 이게 에이전트적(agentic) 워크플로우입니다.

에이전트는 사람 없이 메시징 루프의 양쪽을 스스로 도는 Claude입니다.

  1. 도구를 붙여 Claude에 메시지 전송
  2. Claude가 최종 답 또는 도구 사용 요청으로 응답
  3. 내 코드가 그 도구를 실행
  4. 결과를 다시 Claude에 전달
  5. stop_reason이 end_turn일 때까지 반복
while True:
    response = client.messages.create(
        model="claude-sonnet-4-6", max_tokens=1024,
        tools=tools, messages=messages)
    if response.stop_reason == "end_turn":
        # 최종 답 출력 후 종료
        break
    if response.stop_reason == "tool_use":
        tool_results = []
        for block in response.content:
            if block.type == "tool_use":
                result = run_tool(block.name, block.input)
                tool_results.append({"type":"tool_result",
                    "tool_use_id": block.id, "content": result})
        messages.append({"role":"assistant","content":response.content})
        messages.append({"role":"user","content":tool_results})
루프와 도구는 내가 소유하고, 추론은 Claude가 소유합니다. 모의 날씨 데모부터 프로덕션 컴플라이언스 에이전트까지 루프의 모양은 동일하고 도구와 배관만 달라집니다. 루프를 직접 돌리기 싫으면 매니지드 에이전트가 대신 돌려줍니다.

도구 사용이란?

🎬 영상

Claude는 프로젝트 관리 도구·DB·파일을 스스로 확인할 수 없습니다. 대신 도구(tool)로 외부 데이터·행동에 접근합니다. 도구를 실행하는 건 Claude가 아니라 내 코드입니다.

도구는 name · description · input_schema로 이뤄진 JSON 스키마이며, 요청 본문의 tools 배열로 넘깁니다.

description을 구체적으로! Claude가 호출 여부를 판단하는 근거가 바로 description입니다. 모호하면 도구를 잘못 쓰거나 안 씁니다 — 에이전트 오작동의 1순위 원인.

다중 도구 — Claude가 고르게

도구를 여러 개 주면 Claude가 프롬프트를 읽고 어떤 걸 어떤 순서로 쓸지 스스로 고릅니다(그래서 description이 중요). 루프는 동일하고, tool name으로 분기하는 runTool switch만 추가됩니다. 도구 추가 = 배열에 추가 + case 추가.

Tool runner — 보일러플레이트 제거

SDK(TypeScript·Python·Ruby)의 tool runner는 실제 함수의 타입·독을 읽어 스키마를 자동 생성하고, tool use/result 루프 전체를 내부에서 처리합니다.

const runner = client.beta.messages.toolRunner({
  model: "claude-sonnet-4-6", max_tokens: 1024,
  messages: [{ role: "user", content: "..." }],
  tools: [getWeather, getForecast],   // 평범한 함수를 그대로
});
const finalMessage = await runner.untilDone();

while 루프·stop_reason 분기·JSON 스키마 없이 코드가 크게 줄고, 실제 코드베이스의 기존 함수를 그대로 감싸 쓸 수 있습니다.

확장 사고(thinking)란?

🎬 영상

확장 사고(extended thinking)는 Claude가 최종 응답 전에 단계별로 추론하게 합니다. 내부 추론 토큰(chain of thought)이 생성되고, 그 추론은 숨겨지지 않고 응답에 함께 보입니다.

Opus의 적응형 사고

토큰 예산을 정할 필요 없이 켜기만 하면 Claude가 언제·얼마나 생각할지 동적으로 결정합니다. 깊이는 effort 파라미터로 조절하되, output_config 안에 넣습니다.

response = client.messages.create(
    model="claude-opus-4-7", max_tokens=16000,
    thinking={"type": "adaptive"},
    output_config={"effort": "high"},  # low | medium | high | xhigh | max
    tools=[weather_tool], messages=[...])
쓸 때건너뛸 때
수학·다단계 논리, 코드 디버깅, 규제 분석, 트레이드오프·옵션 비교단순 분류·추출·보일러플레이트 — 지연·비용만 늘고 품질 개선 없음
프로덕션에선 이게 “문제를 하나씩 찾는 에이전트”와 “문제를 연결하는 에이전트”의 차이 — 예: 리포트 3절의 풍하중 스펙이 다른 곳의 재료 스펙과 충돌함을 잡아냄.

내장 도구(Built-in tools)

🎬 영상

서버 도구 — 선언은 내가, 실행은 Anthropic이

서버 도구는 Anthropic 인프라에서 실행됩니다. 내가 실행하지 않으므로 에이전트 루프가 필요 없고, 결과가 같은 응답 안에 담겨 돌아옵니다.

서버 도구기능
Web search인터넷 검색 + 인용 포함 결과
Code execution샌드박스에서 Python 작성·실행
Web fetchURL 전체 내용 가져오기

응답엔 새 블록 타입이 등장합니다 — server_tool_use(도구 호출), 코드 실행 결과 블록, 그리고 일반 text 블록.

주의 · 웹에서 검증됐다고 참인 건 아닙니다. Claude의 작업은 항상 재확인하세요.

클라이언트 도구

또 다른 범주. 내 코드가 도는 곳에서 실행되며 SDK가 스키마·러너를 제공: Memory(세션 간 읽기/쓰기), Bash(영속 셸). “Anthropic이 호스팅” 아이디어는 매니지드 에이전트에서 도구 하나가 아니라 에이전트 전체로 확장됩니다.

Skills

🎬 영상

Skills는 Claude가 특정 작업을 잘하도록 동적으로 로드하는 지침·스크립트·자료 폴더입니다. 중심엔 SKILL.md — 한 번 업로드하고 어떤 messages.create에도 붙일 수 있는 지침 묶음. 내 상태 리포트 형식·리뷰 체크리스트·릴리스 노트 방식을 가르칩니다.

구분역할
ToolsClaude가 무엇을 할 수 있나(데이터·행동 연결)
SkillsClaude가 어떻게 하길 원하나(절차·플레이북)
Skills는 시작 시 전체가 로드되지 않습니다 — 이름·설명만 먼저, 관련되다고 판단할 때 전체를 로드해 컨텍스트를 가볍게 유지.

워크스페이스에 한 번 업로드(client.beta.skills.create)하고 ID로 참조합니다. 요청엔 container.skills 배열로 붙이며(여러 개 레이어링 가능), 절차가 실제 작업을 하도록 code execution과 자주 짝지어 씁니다. (촬영 시점 기준 beta 헤더 필요)

MCP

🎬 영상

도구·스킬·커넥터가 있는데 MCP는 왜 있을까? 답은 통합 코드를 누가 유지보수하느냐입니다. 커스텀 도구로 Asana·Slack·Google을 붙이면, 그 서비스 API가 바뀔 때마다 내가 유지보수해야 합니다.

MCP는 그 유지보수를 서비스 제공자에게 넘깁니다. Asana가 MCP 서버를 게시하고, API가 바뀌면 그들이 서버를 갱신 — 나는 아무것도 안 바꿔도 됩니다.
기능대상
Tools내 것(내부 시스템·DB·독점 API) — 유지보수도 내 몫
Skills내 절차(리포트 템플릿·리뷰 체크리스트)
MCP남의 것(서드파티 서비스) — 제공자가 유지보수
response = client.beta.messages.create(
    model="claude-opus-4-8", max_tokens=1000,
    messages=[{"role":"user","content":"What tools do you have?"}],
    mcp_servers=[{"type":"url","url":"https://mcp.linear.app/mcp",
        "name":"linear","authorization_token":os.environ["LINEAR_MCP_TOKEN"]}],
    tools=[{"type":"mcp_toolset","mcp_server_name":"linear"}],
    betas=["mcp-client-2025-11-20"])

스키마를 하나도 안 씁니다 — Claude가 서버를 introspect해 도구 목록을 가져와 고릅니다. 범위 제한도 가능: default_config.enabled=False로 전부 끄고 특정 도구만 켜서(예: 읽기 전용) 안전하게 씁니다.

컨텍스트 관리

🎬 영상

모든 요청엔 컨텍스트 윈도우가 있고, 100만 토큰도 실전 에이전트에선 생각보다 빨리 소진됩니다. 컨텍스트는 시스템 프롬프트·메시지 기록·도구 정의/결과·첨부·스킬·thinking 블록 등 Claude가 그 턴에 보는 모든 것이며, 들어갈 때·나올 때 모두 과금되고 가득 차면 요청이 실패합니다. 목표는 “전부”가 아니라 “맞는 것”을 넣는 것.

패턴설명
Just-in-time (설계 패턴)전부 미리 로드하지 말고, 지금 필요한 것만. 나머지는 도구로 그때그때 가져오게(예: lookup_building_code).
서버측 compactioncontext_management={"edits":[{"type":"compact"}]} — 임계치 넘으면 옛 턴을 자동 요약. 길이를 직접 추적할 필요 없음.
Prompt caching시스템 프롬프트·도구 정의·긴 문서 등 안정적 부분을 표시해 저비용으로 재사용. 4,000토큰 프롬프트를 시간당 100번 부르면 캐싱이 청구서를 좌우.

Managed Agents · 레슨 11

매니지드 에이전트란?

🎬 영상

Claude Managed Agents는 에이전트를 대규모로 구축·배포하는 API 묶음입니다. 도구·페르소나·역량으로 에이전트를 정의하고, 패키지·네트워크가 갖춰진 샌드박스 환경을 구성한 뒤, 내 앱에서 세션을 발사하면 — Claude가 격리 컨테이너(파일시스템·bash·웹 검색)에서 일합니다.

내부는 익숙한 에이전트 루프(추론→도구→결과→반복)이며, 그 루프를 Anthropic 인프라에서 호스팅해 내가 돌리지 않아도 됩니다.

세 가지 예시

  • 일하는 칸반 보드 — 티켓을 "진행 중"으로 끌면 세션 발사. Lighthouse·Puppeteer가 깔린 환경 + GitHub 레포 마운트 → 감사·최적화. 루브릭 채점기가 별도 컨텍스트에서 평가하고 Claude가 재작업(데모에서 96점까지). 두 번째 티켓을 병렬로.
  • 메모리 있는 반복 리서치 — 매주 SaaS 가격을 추적, Python 비용 분석, Excel 스킬, Slack·Asana(MCP) 게시. 메모리로 지난주와 비교("전주 대비 15%↓").
  • 다중 에이전트 인시던트 대응 — 코디네이터가 세 전문가에게 위임, 공유 파일시스템에서 각자 작업 → 종합. 민감 액션은 권한 정책으로 사람 승인 대기.

구성 블록: Agents · Sessions · Environments · Tools · MCP · Memory · Outcomes(루브릭·채점기) · 다중 에이전트 조율.

첫 매니지드 에이전트 만들기

🎬 영상

직접 만든 while 루프도 많은 기능엔 맞지만, 때로 루프가 수 분~수 시간 돌고 상태·파일·재개가 필요합니다. 그럴 땐 서버에서 돌리지 말고 위임하세요. 매니지드 에이전트는 모든 API 계정에 기본 활성화돼 있습니다.

네 가지 프리미티브 (순서대로)

프리미티브역할
Agent페르소나(모델·시스템 프롬프트·툴셋). 여러 실행에 재사용.
Environment실행 장소(클라우드/로컬·네트워킹).
Session특정 환경에서의 단일 실행 = 작업 단위.
Events드나드는 메시지(행동·도구 호출·결과·응답).
agent = client.beta.agents.create(name="Line Counter",
    model="claude-opus-4-8", system="...",
    tools=[{"type":"agent_toolset_20260401","default_config":{"enabled":True}}])
environment = client.beta.environments.create(name="line-counter-env",
    config={"type":"cloud","networking":{"type":"unrestricted"}})
session = client.beta.sessions.create(agent=agent.id,
    environment_id=environment.id, title="Count lines demo")

with client.beta.sessions.events.stream(session_id=session.id) as stream:
    client.beta.sessions.events.send(session_id=session.id, events=[
        {"type":"user.message","content":[{"type":"text","text":"..."}]}])
    for event in stream:
        if event.type == "session.status_idle": break
중요 · 스트림은 열린 이후의 이벤트만 전달하므로, kickoff 메시지 전에 스트림을 먼저 여세요. 주목할 이벤트: agent.message(텍스트)·agent.tool_use(도구)·session.status_idle(완료).

while 루프를 도는 대신 이벤트를 보내고 읽습니다. 루프가 너무 길거나, 너무 많은 일을 하거나, 중단을 견뎌야 할 때 매니지드 에이전트를, 완전 제어가 필요하면 수동 루프를 고르세요.

Claude Code로 만들기

🎬 영상

API 호출 코드를 손으로 짜도 되지만, 더 빠른 길은 Claude가 대신 짜게 하는 것입니다. 스텁만 있는 파일을 Claude Code에 넘겨 이 코스에서 배운 프리미티브로 채웁니다.

Claude API 스킬

Claude Code엔 내장 Claude API 스킬이 있어 /claude-api로 부르거나, TypeScript SDK 사용을 감지하면 자동 호출됩니다. 없으면 마켓플레이스에서: /plugin marketplace add AnthropicsSkills (끝의 s 주의).

좋은 프롬프트 3요소

  • 바꿀 파일을 지목
  • 쓸 패턴을 지목(예: tool runner)
  • 기대하는 최종 상태를 지목

Claude Code가 타입에 맞춰 함수를 채우고, 파일 끝에 호출을 붙여 실행하고, 에러가 나면 메시지를 읽어 그 자리에서 고칩니다.

기억할 패턴: 도구를 정의하고 → 러너에 넘기고 → 결과를 반환. 매번 외워 타이핑하지 말고 스텁 → 위임 → diff 리뷰.
